# SIYI MK15: итоговая спецификация доступа к кнопкам C и D

Дата фиксации: 2026-09-24.

## 1. Назначение

Этот документ фиксирует результат аппаратного исследования SIYI MK15 для последующего использования в отдельном приложении управления дроном и роботом.

Исследовательская задача завершена: определены программный транспорт, протокол, фактический mapping и живые значения физических кнопок C и D.

## 2. Проверенный программный путь

Устройство:
- SIYI MK15;
- Android 9 / API 28;
- QUALCOMM msm8953_64.

Рабочий транспорт:
- SIYI Datalink UART;
- устройство Linux: `/dev/ttyHS0`;
- скорость: **115200 бод**;
- формат: **8N1**;
- аппаратное управление потоком не используется.

Версия Port Inspector 1.4.0 открывает ttyHS0 нативно через JNI и настраивает termios на том же файловом дескрипторе, через который затем выполняются read/write.

На двух успешных аппаратных сеансах зафиксировано:

```text
native=true
binaryClean=true
ispeed=115200
ospeed=115200
iflag=0x00000000
oflag=0x00000000
lflag=0x00000000
VMIN=1
VTIME=0
```

## 3. Протокол SIYI

### 3.1. Получение mapping

Команда:

```text
CMD_ID = 0x48
```

Она возвращает по два байта описания каждого из 16 каналов:
- physical type;
- entity id.

Фактический ответ исследованного MK15 подтвердил:

```text
CH10 type=1 entity=2 -> C
CH11 type=1 entity=3 -> D
```

Поэтому **на данном пульте C находится на CH10, D — на CH11**.

Важно: mapping в MK15 настраиваемый. Будущее прикладное приложение должно по возможности читать 0x48 при запуске и проверять mapping, а не полагаться только на жёстко заданные номера каналов.

### 3.2. Получение живых RC-каналов

Команда:

```text
CMD_ID = 0x42
freq = 2
```

Проверенный запрос 4 Гц:

```text
55 66 01 01 00 00 00 42 02 B5 C0
```

На MK15 запрос отправляется три раза.

После короткого подтверждения:

```text
cmd=0x42 dataLen=1 data=01
```

пульт начинает непрерывно выдавать кадры:

```text
cmd=0x42
dataLen=32
```

Данные содержат 16 значений `int16 little-endian`: CH1...CH16.

Проверенная частота потока — 4 Гц.

Для прекращения потока:

```text
55 66 01 01 00 00 00 42 00 F7 E0
```

Команду остановки также следует отправить три раза.

## 4. Фактические значения кнопок

### C

Физическая кнопка C:

```text
канал: CH10
отпущена: 1050
нажата:   1950
```

После отпускания значение возвращается к 1050.

### D

Физическая кнопка D:

```text
канал: CH11
отпущена: 1050
нажата:   1950
```

После отпускания значение возвращается к 1050.

Кнопки являются моментальными, без фиксации.

## 5. Аппаратное подтверждение

Использованы два независимых отчёта Port Inspector 1.4.0:

- `MK15_Report_20260924_134701_v1_4_0.zip`;
- `MK15_Report_20260924_210500_v1_4_0.zip`.

Первый сеанс:
- 237 живых channel frames;
- 16 отмеченных действий: 8 C + 8 D;
- CH10 min/max = 1050/1950;
- CH11 min/max = 1050/1950;
- CH10 changeCount = 16;
- CH11 changeCount = 16.

Второй сеанс:
- 154 живых channel frames;
- 12 отмеченных действий: 6 C + 6 D;
- CH10 min/max = 1050/1950;
- CH11 min/max = 1050/1950;
- CH10 changeCount = 12;
- CH11 changeCount = 12.

Итого:
- **391 живой кадр каналов**;
- **14 нажатий C**;
- **14 нажатий D**;
- 28 полностью отмеченных действий;
- каждое действие C дало ровно два перехода CH10 (1050 -> 1950 -> 1050) и не изменило changeCount CH11;
- каждое действие D дало ровно два перехода CH11 (1050 -> 1950 -> 1050) и не изменило changeCount CH10;
- несоответствий в 28 отмеченных действиях не обнаружено.

Это даёт прямое воспроизводимое аппаратное подтверждение связи:
- **C -> CH10**;
- **D -> CH11**.

## 6. Практическая рекомендация для будущего приложения

Наблюдённые аппаратные значения — строго 1050 и 1950. Однако прикладному приложению лучше распознавать состояния диапазонами, а не через точное равенство.

Рекомендуемый консервативный вариант:

```text
value <= 1300 -> отпущена
value >= 1700 -> нажата
иначе         -> промежуточное/неопределённое состояние
```

Это рекомендация для устойчивости, а не измеренный дополнительный диапазон.

Также разумно:
1. при запуске проверить mapping через 0x48;
2. включить 0x42 только тогда, когда действительно нужны RC-каналы;
3. после завершения чтения выключить поток командой freq=0;
4. учитывать предупреждение SIYI: поток RC использует тот же Datalink-интерфейс и может влиять на телеметрический обмен.

### Проверка безопасной частоты и остановки потока

Расширенный исследовательский режим 1.5.5 использовал 20 Гц и во время длительной серии выявил проблему: поток мог пережить перезапуск приложения и не прекратиться после первой команды OFF. Это **не относится к частоте SDK 4 Гц**, но стало основанием для отдельной аппаратной регрессии.

В Port Inspector 1.5.6 исследовательский режим переведён на тот же проверенный режим, который закреплён в этой спецификации:

```text

frequency code = 2
target frequency = 4 Hz
```

На реальном MK15 измерено:

```text
RATE_SAMPLE=1800ms sample frames=8 target=4Hz
RATE_SAMPLE_FRAMES=8
RESEARCH_4HZ=PASS
```

После OFF:

```text

STOP_RESULT=FULL_STOP
MK15_156_QA2=PASS
```

Один кадр после команды относится к уже находившемуся в тракте обмену; затем поступление прекратилось.
