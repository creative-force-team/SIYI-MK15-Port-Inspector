# SIYI MK15 Port Inspector 1.5.0 — исследование физических органов управления

Дата: 4 октября 2026 года.

## Цель версии

Версия 1.5.0 продолжает завершённое исследование C/D и предназначена для объективного исследования остальных физических органов SIYI MK15.

Итог каждого опыта должен связывать:

**физический орган → SIYI entity → RC channel → реальные значения/состояния → повторяемость → исследовательская классификация.**

Эта версия **не назначает** HOLD, RTH или MANUAL. Назначение будет отдельным решением после анализа измерений.

## Безопасная граница

Режим исследования:

- не посылает команды полётному контроллеру;
- не формирует actuator-команды;
- не изменяет SIYI mapping;
- не меняет RC-конфигурацию;
- использует только уже проверенный SIYI Datalink на `/dev/ttyHS0`;
- читает mapping командой `0x48`;
- запрашивает живые RC-каналы `0x42` с частотой 20 Гц;
- при остановке выключает поток `0x42`.

Испытания проводить **только на столе, не в полёте и без работающей силовой установки**. Поток `0x42` использует тот же Datalink, что и другая телеметрия, поэтому во время исследования не следует параллельно запускать программы, которые конкурируют за этот интерфейс.

## Что нового на экране

Добавлена отдельная строка **«Исследование органов управления»**.

Доступны:

- выбор известного органа: A, B, SA, SB, SC, LD, RD, C/D как контроль, J1–J4, OTHER;
- произвольное имя для дополнительного органа при выборе OTHER;
- вид опыта: BUTTON, SWITCH_3POS, ANALOG, STICK, OTHER;
- «Начать запись органа»;
- «Завершить запись»;
- «Остановить исследование».

В таблице 16 каналов во время режима показываются:

- channel;
- entity type;
- entity ID;
- имя из runtime mapping;
- Current;
- Min;
- Max;
- Delta относительно исходного состояния;
- LOW / CENTER / HIGH;
- число изменений;
- время последнего изменения.

Строка, изменившаяся совсем недавно, подсвечивается.

## Как проводить один опыт

Перед началом каждого опыта выбрать **только один** физический орган.

### Кнопка

1. Нажать «Начать запись органа».
2. Не трогать ничего другого.
3. Выполнить не менее пяти полных циклов нажатие → отпускание.
4. Полезно сделать несколько обычных и несколько коротких нажатий.
5. Нажать «Завершить запись».

### Трёхпозиционный переключатель

1. Начать запись.
2. Несколько раз последовательно пройти все три положения.
3. Не трогать другие органы.
4. Завершить запись.

### Аналоговый орган

1. Начать запись из нейтрали/обычного положения.
2. Один край.
3. Другой край.
4. Возврат в нейтраль.
5. Повторить не менее пяти раз.
6. Завершить запись.

### J1–J4

Исследуются **только для идентификации**. Их обнаружение не означает, что их следует использовать как кнопки приложения.

## Предпочтительный порядок для Сергея

1. C — контрольный опыт, 5 циклов.
2. D — контрольный опыт, 5 циклов.
3. A — 5–10 нажатий.
4. B — 5–10 нажатий.
5. SA — все положения не менее 5 циклов.
6. SB — все положения не менее 5 циклов.
7. SC — все положения не менее 5 циклов.
8. LD — весь диапазон не менее 5 циклов.
9. RD — весь диапазон не менее 5 циклов.
10. Иные кнопки/переключатели/вращающиеся органы — по одному, через OTHER с понятным именем.
11. J1–J4 — в самом конце, только если требуется полный инвентарь.

Если во время одного опыта неожиданно меняются несколько каналов — **ничего не исправлять вручную**. Завершить опыт как есть: это важный результат.

## Контроль правильности измерителя

Из предыдущего исследования известно:

- C → type=1/entity=2 → CH10;
- D → type=1/entity=3 → CH11;
- отпущено около 1050;
- нажато около 1950.

Новый опыт C/D нужен только как контроль того, что текущий измеритель на том же пульте продолжает видеть известный эталон.

Если C/D внезапно дают другой mapping или значения, дальнейший инвентарь лучше остановить и сначала сохранить ZIP.

## Что попадает в ZIP

Стандартный отчёт дополнен:

- `SUMMARY.md` — человекочитаемый итог записанных опытов;
- `controls.json` — машиночитаемый список опытов и найденных каналов;
- `controls.csv` — плоская сводка;
- `events.csv` — сырые переходы значений с временем и номером опыта;
- `mapping_raw.txt` — сырой runtime mapping и его расшифровка;
- прежние системные снимки, журналы и диагностика Port Inspector.

Программа намеренно **не объявляет APP_CANDIDATE автоматически**. Стики J1–J4 маркируются RC_CONTROL, прочие новые органы остаются UNKNOWN до анализа повторяемости и возможных конфликтов со штатным RC-контуром.

## Что Сергей должен вернуть

После выполнения серии нажать:

**ZIP → thesystem**

Если отправка не удаётся, сохранить через **ZIP → Download** и передать архив обычным способом.

Никаких ручных таблиц составлять не нужно: главное — аккуратно записывать по одному органу за опыт и давать ему правильное физическое имя.

## Критерий следующего этапа

После получения ZIP мы должны для каждого проверенного органа установить только фактически измеренное:

- entity type / entity ID;
- реальный channel;
- значения устойчивых состояний или диапазон;
- повторяемость;
- быстрые/переходные значения;
- влияние на один или несколько каналов;
- предварительную классификацию RC_CONTROL / APP_CANDIDATE / UNKNOWN.

Только после этого можно обсуждать кандидатов для HOLD, RTH и MANUAL.
