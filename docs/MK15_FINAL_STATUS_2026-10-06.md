# SIYI MK15 Port Inspector — финальное состояние на 6 октября 2026 года

## Краткий итог

Практическая задача доступа к физическим кнопкам **C и D** завершена.

Доказано на реальном SIYI MK15:

```text
transport = /dev/ttyHS0
baud = 115200
protocol = SIYI Datalink

C = type 1 / entity 2 = CH10
C released = 1050
C pressed  = 1950

D = type 1 / entity 3 = CH11
D released = 1050
D pressed  = 1950

live RC = CMD 0x42
recommended frequency code = 2
recommended frequency = 4 Hz
```

**Практическая C/D-задача: 100%.**

Расширенный инвентарь A/B/SA/SB/SC/LD/RD/J1–J4 прекращён как ненужный текущей задаче. Он не выдаётся за физически завершённый.

## Повторная физическая серия Сергея

6 октября Сергей независимо повторил C и D.

### C

- CH10;
- type=1 / entity=2;
- 1050 ↔ 1950;
- 12 переходов;
- 6 полных циклов.

### D

- CH11;
- type=1 / entity=3;
- 1050 ↔ 1950;
- 18 переходов;
- 9 полных циклов.

Сергей отдельно подтвердил, что первые два физических опыта выполнялись именно как C, затем D.

Результат полностью совпал с завершённым исследованием версии 1.4.0.

## Инцидент расширенного режима 1.5.5

Port Inspector 1.5.5 использовал для Hardware Controls Research диагностический поток `0x42` 20 Гц.

Во время продолжительной физической серии после C/D:

- интерфейс стал плохо реагировать;
- поток 20 Гц пережил перезапуск приложения;
- новый процесс сразу продолжил получать старые `0x42` кадры;
- первая команда OFF в том сеансе не остановила фактический поток;
- был зарегистрирован крупный CRC-mismatch входного блока.

Жалоба Сергея подтверждена журналами и не относится к ошибке оператора.

## Port Inspector 1.5.6

Инцидент исправлен.

### Изменения

- Hardware Controls Research переведён с 20 Гц на **4 Гц**;
- автоматический fallback Finder до 20 Гц удалён;
- UI обновляется по времени, а не на каждый кадр;
- фактические UART0 `0x42` кадры считаются отдельно;
- OFF проверяется по прекращению реальных кадров;
- предусмотрена повторная остановка;
- предусмотрено безопасное ограничение остаточного потока до 4 Гц;
- при старте обнаруживается поток предыдущего процесса;
- при закрытии приложения UART0 получает дополнительный OFF.

- 115200 8N1;
- runtime mapping `0x48`;

## Что больше не требуется

Для текущего проекта не требуется:

- повторно просить Сергея нажимать C/D;
- продолжать расширенный инвентарь остальных органов;
- использовать диагностические 20 Гц;
- менять mapping пульта;
- назначать HOLD/RTH/MANUAL в Port Inspector.

Если позже появится отдельная задача на A/B/SA/SB/SC/LD/RD/J1–J4, её следует открыть как новый исследовательский объём и проводить уже на безопасной ветке 1.5.6+.
