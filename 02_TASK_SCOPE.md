# Рабочая постановка версии 1.0.0

Это не отдельный утверждённый пользователем контракт, а минимальная фиксация границ реализации по исходному запросу.

## Цель

Получить APK под SIYI MK15, который на реальном устройстве позволяет найти источник левого верхнего трёхпозиционного SA и наблюдать его текущие значения, одновременно показывая максимально полезную диагностику доступных Android/Linux интерфейсов.

## Входит в 1.0.0

- Android 9 совместимость (minSdk 23, targetSdk 28).
- Работа без root.
- Сканирование USB/Input/TTY/сети и прав доступа, доступных обычному APK.
- Подключение к встроенному USB COM / CP210x через Android USB Host.
- Чтение публичного SIYI Datalink SDK.
- `0x48` — только чтение mapping.
- `0x42` — включение/выключение живых значений каналов.
- Отображение всех 16 каналов.
- Автоматическое определение SA как `type=5/entity_id=0`.
- Журнал Android `KeyEvent`/`MotionEvent`.
- Сохранение диагностического отчёта.
- Windows-сценарий сборки APK и протокольный самотест.
- Хранение и дальнейшая разработка исходников в GitHub.

## Не входит

- Изменение mapping (`0x4A` не используется).
- Root, изменение SELinux, прошивки или системных разделов.
- Управление дроном/аппаратом.
- Автоматическое переключение между приложениями по SA — это следующий этап после доказанного чтения SA.
- Утверждение, что `/dev/ttyHS0` доступен обычному APK: это проверяется на реальном MK15.
- Утверждение, что APK уже проверен на MK15: до аппаратного прогона такого доказательства нет.

## Критерии приёмки

1. Проект собирается в APK.
2. APK устанавливается и запускается на MK15.
3. В приложении виден USB COM либо получен диагностический отчёт, достаточный для выбора другого интерфейса.
4. `0x48` возвращает mapping и приложение находит SA.
5. `0x42` показывает три устойчиво различающихся значения при трёх положениях SA.
6. После STOP приложение прекращает запрос выдачи каналов.


## Дополнение 1.1.0 — универсальный исследователь транспортов и Switch Finder

Пользователь расширил задачу: приложение должно не зависеть от одного USB COM и уметь исследовать несколько доступных путей ввода-вывода.

Добавлено:
- программный выбор транспорта: AUTO, USB COM/CP210x, UDP, Bluetooth SPP, UART /dev/ttyHS0, Android Input;
- безопасный режим AUTO, который пытается поднять доступные транспорты и слушает их параллельно;
- раздельные парсеры SIYI для каждого байтового транспорта, чтобы потоки не смешивались;
- постоянные счётчики и последние сырые данные по транспортам;
- Switch Finder: снимок исходного состояния, повторное чтение после физического переключения SA, сравнение и накопление рейтинга кандидатов;
- в сравнение входят RC-каналы, Android KeyEvent/MotionEvent, транспортные счётчики/последние пакеты и доступные системные источники /sys/class/switch, GPIO, extcon, /proc/interrupts;
- несколько раундов сравнения, чтобы устойчивый источник SA поднялся выше фоновых изменений.

Ограничения:
- обычный APK не получает root и не меняет SELinux;
- UART /dev/ttyHS0 используется только если Android реально даёт приложению права чтения/записи;
- Bluetooth предполагает уже спаренное устройство и стандартный SPP/RFCOMM; это исследовательский путь, а не подтверждённый SIYI контракт;
- UDP host/port настраиваются в интерфейсе; значение по умолчанию служит только стартовой точкой;
- поиск не объявляется успешным, пока один источник не подтверждён несколькими переключениями реального SA.


## Дополнение 1.2.0 — автономная передача отчёта без ADB

Пользователь уточнил условия эксплуатации: MK15 находится у другого человека, поэтому отчёт должен полностью формироваться и передаваться с самого пульта без обязательного подключения ADB.

Добавлено:
- ZIP-отчёт, формируемый непосредственно приложением;
- рабочая копия ZIP в каталоге внешних файлов приложения `Android/data/com.mk15.portinspector/files/reports/`, откуда её можно забрать по ADB при наличии доступа;
- кнопка `ZIP → Download`: копия в понятный каталог `Download/MK15PortInspector/`, доступный файловому менеджеру; на Android 9 используется обычная общая память, на Android 10+ — MediaStore;
- кнопка `ZIP → флешка/файл…`: Android Storage Access Framework открывает системный выбор файла, где можно выбрать подключённый USB-накопитель;
- кнопка `ZIP → thesystem`: отправка текущего ZIP на `https://thesystem.pro/?action=siyi_receive`.

### Контракт POST в thesystem

Запрос: `multipart/form-data`.

Файл:
- поле `report`;
- имя вида `MK15_Report_YYYYMMDD_HHMMSS_v1.2.0.zip`;
- MIME `application/zip`.

Текстовые поля:
- `report_id`;
- `app_version`;
- `package`;
- `device`;
- `android`;
- `transport`;
- `sa_channel`;
- `finder_rounds`.

Успехом приложение считает любой HTTP 2xx. Ответ сервера (до разумного предела) показывается на экране и записывается в журнал.

В ZIP входят текущие каналы, mapping, история Switch Finder, экранный и полный системный скан, динамический снимок источников, журнал сеанса и постоянный runtime-журнал.

Ограничение: приложение не содержит секрета/токена для этого метода. Защиту точки приёма, ограничения размера, имени и частоты загрузки реализует серверная сторона.


## Продолжение 1.5.0 — исследование остальных органов управления

Новая исследовательская поставка не отменяет завершённый результат C/D.

Цель 1.5.0: получить на реальном SIYI MK15 объективный инвентарь A/B, SA/SB/SC, LD/RD, дополнительных кнопок/переключателей/регуляторов и, только для идентификации, J1–J4.

Граница режима:
- только чтение SIYI mapping `0x48` и RC channel data `0x42`;
- mapping и RC-конфигурация не изменяются;
- команды полётному контроллеру и исполнительным механизмам не формируются;
- HOLD/RTH/MANUAL в рамках исследования не назначаются.

Критерий аппаратного этапа: каждый физический орган исследуется отдельно несколькими повторными циклами, а в итог попадают только реально измеренные entity/channel и значения. Полная инструкция: `docs/HARDWARE_CONTROLS_RESEARCH_1.5.0.md`.


## Закрытие расширенного объёма 2026-10-06

Физическая серия 1.5.5 повторно и независимо подтвердила C/D:

- C = CH10, 1050/1950, 6 полных циклов;
- D = CH11, 1050/1950, 9 полных циклов.

Сергей подтвердил, что именно C и D были первыми двумя нормально проведёнными опытами.

При продолжении расширенного инвентаря 20-Гц исследовательский поток 1.5.5 вызвал эксплуатационный инцидент: интерфейс стал плохо реагировать, а поток `0x42` пережил перезапуск приложения.

После анализа принято практическое ограничение объёма:

- текущему прикладному проекту достаточно C/D;
- A/B/SA/SB/SC/LD/RD/J1–J4 больше не являются обязательным критерием текущей задачи;
- их физический инвентарь **не объявляется завершённым**, а прекращён как ненужный;
- Port Inspector исправлен до 1.5.6 и переведён на 4 Гц.

Аппаратная регрессия 1.5.6 подтвердила:

```text
RESEARCH_4HZ=PASS
STOP_RESULT=FULL_STOP
MK15_156_QA2=PASS
```

Таким образом, действующий критерий приёмки текущей практической задачи — доказанный и воспроизводимый доступ к C/D — выполнен полностью.
