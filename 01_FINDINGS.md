# Исследование SIYI MK15: где находится левый переключатель SA

## Факт из приложенного MK15 User Manual V1.1

В таблице `1.2.2 Button/Switch Types and Default Channel Definitions` указано:

- CH5 → 3-Stage Switch SA;
- CH6 → SB;
- CH7 → SC.

Там же указано, что всего у MK15 13 физических и 16 коммуникационных каналов.

Раздел `3.1.4 Channel Mapping` прямо говорит, что физические органы управления можно свободно переназначать на коммуникационные каналы. Следовательно, CH5 — заводское назначение, но надёжная программа должна читать фактический mapping.

## Факт из актуального опубликованного SIYI Datalink SDK

Современное руководство MK15 содержит публичный двоичный протокол SIYI.

### `0x48 Request All Channel Mappings`

Ответ содержит для каждого CH1..CH16 два байта: `type` и `entity_id`.

Для MK15:

| Физический орган | type | entity_id |
|---|---:|---:|
| J1 | 0 | 0 |
| J2 | 0 | 1 |
| J3 | 0 | 2 |
| J4 | 0 | 3 |
| LD | 0 | 4 |
| RD | 0 | 5 |
| **SA** | **5** | **0** |
| SB | 5 | 1 |
| SC | 5 | 2 |
| A | 1 | 0 |
| B | 1 | 1 |
| C | 1 | 2 |
| D | 1 | 3 |

Поэтому приложение ищет `type=5/entity_id=0`, а не жёстко CH5.

### `0x42 Request Channel Data`

Команда включает выдачу 16 значений каналов. Каждое — `int16_t`, заводской диапазон примерно `1050..1950`.

Коды частоты:

- 0 — выключить;
- 1 — 2 Гц;
- 2 — 4 Гц;
- 3 — 5 Гц;
- 4 — 10 Гц;
- 5 — 20 Гц;
- 6 — 50 Гц;
- 7 — 100 Гц.

SIYI предупреждает, что такой вывод может влиять на телеметрию, потому что использует тот же интерфейс. В актуальной редакции v1.8 для запуска/остановки указано отправлять команду три раза подряд.

Официальные тестовые запросы:

```text
4 Гц: 55 66 01 01 00 00 00 42 02 B5 C0
OFF:  55 66 01 01 00 00 00 42 00 F7 E0
0x48: 55 66 01 00 00 00 00 48 89 1D
```

Эти три кадра воспроизводятся нашим `SiyiProtocol` байт-в-байт и проверяются `ProtocolSelfTest`.

## Как Android-приложение добирается до протокола

В опубликованном SDK перечислены четыре интерфейса:

1. UART `/dev/ttyHS0`, 115200 бод;
2. USB COM (USB-to-Serial), скорость совпадает с Datalink Baud Rate;
3. Bluetooth;
4. Upgrade Port / виртуальный последовательный порт.

Старое руководство отдельно поясняет, что USB COM построен на встроенном **CP2102** и используется Android QGroundControl.

### Почему выбран USB COM

Это наиболее практичный путь для обычного APK без root:

- Android имеет штатный `UsbManager` и механизм выдачи приложению разрешения на конкретное USB-устройство;
- не требуется системная подпись;
- не требуется доступ к `/dev/ttyHS0`, который может быть закрыт правами Linux/SELinux;
- это штатно задокументированный SIYI транспорт.

Приложение при этом всё равно показывает наличие и права `/dev/ttyHS0`, чтобы на реальном MK15 не терять альтернативный путь.

## Проверяемый вывод

Предположение «SA есть только как RC channel 5» близко к сути, но **канал 5 не следует считать неизменным**, потому что mapping переназначаемый.

Правильный алгоритм:

1. `0x48` → найти канал, где `(type=5, entity_id=0)`;
2. `0x42` → читать живые `CH1..CH16`;
3. брать значение найденного канала;
4. на заводской конфигурации ожидается CH5 и три положения около `1050/1500/1950`.

Это реализует версия 1.0.0.


## Продолжение исследования после C/D

Предыдущее аппаратное исследование доказало рабочий путь C/D: native UART `/dev/ttyHS0`, 115200 8N1, runtime mapping `0x48`, channel data `0x42`; на исследованном пульте C=CH10, D=CH11, состояния 1050/1950.

Версия 1.5.0 использует этот доказанный измерительный путь как основу для исследования остальных органов. C/D в новом опыте являются контрольным эталоном, а не кандидатами для новых назначений.

Для новых органов номера каналов и значения заранее не принимаются: они должны быть получены только из runtime mapping и аппаратных опытов.
